# PR 생성

## 절차

### 1. 현재 상태 확인
```!
git status
git log --oneline -10
```

- 현재 브랜치 확인
- 커밋되지 않은 변경사항이 있으면 먼저 커밋 안내

### 2. 대상 브랜치 결정
- `feature/*` → `stage`
- `hotfix/*` → `main`
- 인자로 대상 브랜치가 지정되면 그것을 사용 ($0)

### 3. 변경사항 분석
- base 브랜치와의 diff 확인
- 모든 커밋 메시지 확인
- 영향받는 기능/페이지 파악

### 4. remote push
```bash
git push -u origin <현재브랜치>
```

### 5. PR 생성
- PR 템플릿에 맞게 작성:

```
## 요약
왜 이 변경이 필요한지 한두 줄

## 변경사항
- 변경 1
- 변경 2

## 영향 범위
- 영향받는 기능/페이지
- 사이드이펙트 여부

## 테스트
- [ ] 테스트 항목 1
- [ ] 테스트 항목 2

## 스크린샷
(UI 변경 시)
```

- `gh pr create` 명령어 사용
- 제목은 한국어, 70자 이내

## 절대 금지
- PR 머지 (사용자가 직접 수행)
- main, stage에 직접 push
